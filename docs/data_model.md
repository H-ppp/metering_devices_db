# Модель данных

Модель спроектирована с учетом нормализации, поддержки историчности данных (перемещение и смена типа счетчиков) и высокой производительности на больших объемах данных.

Ниже приведено подробное описание разработанной модели.


## Основные объекты базы данных


### Таблица `locations` (Места размещения)
Справочник объектов недвижимости, где устанавливаются приборы учета. Хранит статическую информацию о локации.

| Атрибут | Тип данных | Назначение и ограничения |
| :--- | :--- | :--- |
| `location_id` | `BIGINT` | **Первичный ключ (PK).** Уникальный идентификатор места размещения. Генерируется автоматически (`GENERATED ALWAYS AS IDENTITY`) |
| `address` | `TEXT` | Текстовое описание адреса или наименования места |
| `location_type` | `TEXT` | Тип локации. Ограничен проверкой (`CHECK`): `'apartment'` (квартира), `'house'` (частный дом), `'common_area'` (общедомовое). |
| `created_at` | `TIMESTAMPTZ` | Дата и время создания записи в системе (по умолчанию `NOW()`) |


#### 2. Таблица `meters` (Реестр приборов учета)
Хранит инвариантные (неизменяемые) данные о физическом устройстве. **Не содержит** информации о месте или типе ресурса, так как один и тот же физический счетчик может быть перенесен в другое место или переквалифицирован (например, со счетчика горячей воды на счетчик холодной).

| Атрибут | Тип данных | Назначение и ограничения |
| :--- | :--- | :--- |
| `meter_id` | `BIGINT` | **Первичный ключ (PK).** Уникальный идентификатор прибора. |
| `serial_number` | `VARCHAR(50)` | Заводской серийный номер счетчика. Имеет ограничение `UNIQUE` для предотвращения дублирования. |
| `created_at` | `TIMESTAMPTZ` | Дата и время регистрации прибора в системе. |


#### 3. Таблица `meter_installations` (История установок)
Связывает физический прибор (`meters`) с местом размещения (`locations`) на определенном промежутке времени. Позволяет корректно рассчитывать показания даже при замене счетчика или смене его типа внутри отчетного периода и обеспечивает историчность данных.

| Атрибут | Тип данных | Назначение и ограничения |
| :--- | :--- | :--- |
| `installation_id` | `BIGINT` | **Первичный ключ (PK).** Уникальный идентификатор конкретного факта установки. |
| `meter_id` | `BIGINT` | **Внешний ключ (FK).** Ссылка на таблицу `meters`. При удалении прибора каскадно удаляются его установки (`ON DELETE CASCADE`). |
| `location_id` | `BIGINT` | **Внешний ключ (FK).** Ссылка на таблицу `locations`. |
| `meter_type` | `meter_type` | Тип измеряемого ресурса (ENUM: `'cold_water'`, `'hot_water'`, `'electricity'`, `'gas'`). Может отличаться для разных установок одного и того же `meter_id`. |
| `installation_date` | `DATE` | Дата начала эксплуатации прибора в данной локации. |
| `deinstallation_date`| `DATE` | Дата демонтажа прибора. Значение `NULL` означает, что счетчик установлен и активно передает показания. |
| `initial_reading` | `NUMERIC(12,4)`| **Показание по умолчанию.** Значение на счетчике в момент его установки, используемое как база для расчетов. |

*Таблица содержит `CHECK`-ограничение, гарантирующее, что дата демонтажа всегда позже даты установки.*


#### 4. Таблица `readings` (Показания приборов)
Хранилище ежедневных значений счетчиков. Является **секционированной таблицей** (`PARTITION BY RANGE (reading_date)`), разбитой на месячные партиции. Это ключевой элемент для обеспечения высокой производительности при хранении 100 млн+ записей.

| Атрибут | Тип данных | Назначение и ограничения |
| :--- | :--- | :--- |
| `installation_id` | `BIGINT` | **Часть составного первичного ключа (PK).** Ссылка на `meter_installations`. Привязка показания к конкретной *установке*, а не просто к счетчику, гарантирует историческую точность типа и места. |
| `reading_date` | `DATE` | **Часть составного первичного ключа (PK) и ключ секционирования.** Дата снятия показания. |
| `value` | `NUMERIC(12,4)`| Фактическое значение, переданное прибором учета в указанную дату. |


## Отношения между объектами

Архитектура базы данных построена вокруг центрального связующего элемента - таблицы истории установок (meter_installations). Две другие таблицы (locations и meters) являются независимыми справочниками, которые не ссылаются друг на друга, но оба ссылаются на эту центральную таблицу.

Таблицы meters (справочник приборов) и meter_installations (история установок) связаны отношением "один-ко-многим" по полю meter_id. 

Один физический счетчик, записанный в таблице meters по своему уникальному серийному номеру, может иметь множество записей об установках в таблице meter_installations в течение своего жизненного цикла.

Таблицы locations (справочник адресов/объектов) и meter_installations (история установок) также связаны отношением "один-ко-многим" по полю location_id. 

Одно конкретное место размещения (например, «Квартира №5»), записанное в таблице locations, может быть связано с множеством разных установок за все время наблюдения.

Таблицы meter_installations (история установок) и readings (ежедневные показания) связаны отношением "один-ко-многим" по полю installation_id. 

Одна конкретная запись об установке (определенный счетчик, в определенном месте, с определенным типом и в определенный период времени) генерирует множество ежедневных записей показаний в таблице readings.


## Описание функции get_monthly_meter_report


Функция get_monthly_meter_report инкапсулирует бизнес-логику по расчету ежемесячных показаний. Она спроектирована так, чтобы корректно обрабатывать пограничные ситуации (замена счетчика в середине месяца, отсутствие показаний, установка нового прибора) и при этом работать максимально быстро на больших объемах данных.

Функция принимает два аргумента:
- p_location_id (BIGINT)  - идентификатор места размещения (квартиры, дома и т.д.), по которому формируется отчет;
- p_report_month (DATE) — любая дата из отчетного месяца. Функция автоматически определит начало и конец этого месяца


Функция возвращает таблицу, где каждая строка соответствует одной установке счетчика, активной в данном месяце. Возвращаемые колонки:
- serial_number: серийный номер прибора;
- meter_type: тип ресурса (холодная/горячая вода, газ, электричество) именно для этого периода установки;
- reading_start: первое зафиксированное показание в отчетном месяце;
- reading_end: последнее зафиксированное показание в отчетном месяце; 
- consumption: рассчитанный расход (reading_end - reading_start);
- initial_reading: показание по умолчанию на момент установки (важно, если в месяце не было передано ни одного показания);
- location_address: адрес места размещения
